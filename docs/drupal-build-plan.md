# خطة بناء المنصة على دروبل (novatera.space)

> المرجع الوحيد لبناء المنصة على دروبل. أي جلسة بتشتغل على البناء تقرأه أول، وتمشي بالمراحل بالترتيب، وتعلّم على كل مرحلة لما تخلص.
> الموقع الحالي (Astro، مجلد `site/`) هو **المرجع للتصميم والسلوك**. دروبل هو **المرجع للبيانات**.

---

## ٠. القواعد اللي ممنوع تنكسر

1. **التصميم نفسه بالزبط.** ما في تصميم جديد. الـ CSS والـ JS والـ SVG والخطوط من `site/src/styles` و`site/src/scripts` و`site/src/city` و`site/src/model` بتنتقل كما هي. كل مكوّن `.astro` بيصير قالب Twig بنفس الـ HTML والـ classes.
   - دروبل ما بيعرض صفحة بدون "ثيم" تقني. اسمه `platform`، وهو مجرد وعاء لملفات موقعنا. **ما فيه ولا سطر تصميم من عنده**، وما منستعمل Olivero ولا Claro للواجهة (Claro للوحة الأدمن بس).
2. **الصفحة الرئيسية بالترتيب:** Hero3D ← Journey ← CityTeaser ← Projects. بتنتقل زي ما هي بدون أي تعديل. `HeroBoards` و`StoreNote` مش مستعملين وما بينحطّوا.
3. **ممنوع ذكر "توصيل مجاني"** بأي مكان.
4. **ممنوع نوعد إنّا بننفّذ المشروع للطالب** قدام اللجنة. الشغل والتسليم على الطالب.
5. **بدون إيموجي.** أيقونات SVG من `site/src/data/icons.ts` بس.
6. **لغة الواجهة عربي RTL، بلهجة أردنية**، نفس النصوص الموجودة بالموقع حرفياً.
7. **سعر غلط أسوأ من سعر قديم.** أسعار القطع من أبيلا (`abela.json`)، والربط من القوائم المدققة (`partmap.json` و`partalt.json` و`partblock.json`). ممنوع أي مطابقة أوتوماتيكية جديدة بدون مراجعة بالعين.
8. **قبل أي أمر بيكتب على السيرفر:** نسخة احتياطية موجودة، ووضع الصيانة شغّال، والأمر بينعرض على نغم قبل ما يتنفّذ (وضع Ask).

## ٢. الهيكل التقني

```
drupal/
  themes/custom/platform/          ← وعاء التصميم (مش تصميم جديد)
    platform.info.yml               (base theme: false، regions بسيطة)
    platform.libraries.yml          (global.css, store.css, project.css, auth.css, community.css + سكربتات الموقع)
    css/  js/  fonts/  img/         ← منسوخة من site/ كما هي
    templates/
      html.html.twig  page.html.twig        ← من layouts/Base.astro
      partials/header.html.twig  footer.html.twig  whatsapp-fab.html.twig  chat-advisor.html.twig
      front/hero3d  journey  city-teaser  projects      ← الصفحة الرئيسية
      store/…  project/…  community/…  city/…  account/…
  modules/custom/
    platform_core/        ← الإعدادات العامة، الأيقونات، الروابط، الصفحات الثابتة
    platform_catalog/     ← المشاريع + ربط القطع + الاستيراد
    platform_points/      ← سجل النقاط + القواعد + الكوبونات + الدعوات
    platform_community/   ← الجامعات، المشرفين، المنشورات، الردود، مواعيد التسليم
    platform_city/        ← المباني + الإعجابات + الزيارات + التعليقات
    platform_admin/       ← طوابير الموافقة + "مشروع من فكرة"
```

**قاعدة الكود:** المنطق بـ PHP (services وcontrollers وentity hooks)، والعرض بـ Twig. التفاعل بالواجهة بيضل بنفس سكربتات الموقع، بس بيقرأ ويكتب على دروبل بدل localStorage، عن طريق routes JSON صغيرة بموديولاتنا (`/api/platform/...`) عليها CSRF token وصلاحيات.

**موديولات دروبل المطلوبة (contrib):**

| الموديول | ليش |
|---|---|
| `commerce` (موجود) | المتجر، السلة، الطلب، الكوبونات |
| `social_auth_google` أو `openid_connect` (الموجود بنوفاتيرا) | التسجيل والدخول بالجيميل |
| `pathauto` | روابط زي الموقع الحالي |
| `flag` | الإعجاب بالمباني ومتابعة المجتمعات |
| `field_permissions` | الرقم الجامعي مخفي عن الكل إلا صاحبه والأدمن |
| `private_message` | الدردشة الخاصة بين الطلاب (إذا انحسم، شوف القسم ١١) |
| `views_bulk_operations` | موافقات الأدمن بالجملة |
| `honeypot` | حماية النماذج من السبام |

## ٣. أنواع البيانات

### ٣.١ التصنيفات (Taxonomy)
| المفردات | الحقول | المصدر |
|---|---|---|
| `store_category` | الاسم، slug، أيقونة، وصف قصير، ترتيب | `storecats.ts` (19 قسم) |
| `project_category` | الاسم | حقل `c` بـ `projects.json` |
| `project_level` | سهل / متوسط / متقدم | حقل `ln` |
| `university` | الاسم، slug، **الاختصار الإنجليزي**، المدينة، نطاقات بريد الجامعة، شعار | `universities.ts` + `unimail.ts` (28 جامعة) |
| `community_space` | الاسم، slug، النوع (`general` / `news` / `uni`)، الوصف | `spaces.ts` — المجتمع العام والإعلانات، وصف لكل جامعة |
| `post_kind` | سؤال تقني، شغلي، أدوّر على شريك، مصدر مفيد، موعد تسليم (للمشرف بس)، بدي تعديل على مشروع | `community/communities.ts` |

### ٣.٢ القطع (Commerce Product: نوع `part`)
- المنتج: العنوان (اسم أبيلا)، القسم (`store_category`)، الصورة (رابط أبيلا، ومعها صورة بديلة للمكسورة)، رابط أبيلا، `abela_id` (الـ slug، فريد).
- المتغيّر (variation): SKU = `abela_id`، والسعر بالدينار (JOD) = سعر أبيلا **بدون هامش** (قرار نغم).
- **المنتجات الموجودة بنوفاتيرا بتتحدّث بمكانها** (مطابقة بالاسم مثل `tools/abela-import.py`)، عشان صورها والطلب القديم ما يخربوا. الجديد بينضاف، واللي مش عند أبيلا بيتعطّل (unpublish) بدل ما ينمسح.

### ٣.٣ المشاريع (Node: `project`)
| الحقل | النوع | من |
|---|---|---|
| العنوان، الوصف، المشكلة | text | `t`، `d`، `prob` / `details.problem` |
| التصنيف، المستوى | term ref | `c`، `ln` |
| فكرة حصرية + نطاق التكلفة | bool + text | `x`، `details.range` |
| الخطوات | multi (عنوان + نص) | `details.steps` |
| المميزات، التحديات | multi text | `details.feats`، `details.chals` |
| المجسم ثلاثي الأبعاد | JSON | `site/src/model` (نفس المولّد، بدون تغيير الشكل) |
| مجموعات القطع | Paragraph `part_group` | `details.parts` |
| الإضافات | Paragraph `part_option` | `details.extras` |
| التكلفة | محسوبة تلقائياً | مجموع الخيارات الافتراضية × الكمية |

**Paragraph `part_group`:** الاسم، أساسي؟، الكمية، وخيارات (`part_option`).
**Paragraph `part_option`:** الاسم المعروض، الوصف، افتراضي؟، **ومنتجات المتجر** (قائمة: منتج + كمية)، والملاحظة (`alt` / `set` / `node` / `print` / `other` من `partalt.json`).
- السعر = مجموع أسعار منتجاتها من المتجر. **ما في سعر مكتوب بإيدنا**، وهيك أي تحديث لأبيلا بيحدّث المشاريع لحاله.
- خيار بدون منتج (علبة بتنطبع، أو قطعة مش متوفرة) بيضل إله سعر تقديري يدوي، مع ملاحظته.

### ٣.٤ حساب الطالب (User)
| الحقل | ملاحظة |
|---|---|
| الاسم المعروض، نبذة | عام |
| الجامعة | term ref، **لازم بريد الجامعة يطابق نطاقها** للطالب |
| التخصص، السنة | عام |
| الرقم الجامعي | **مخفي عن الكل** (field_permissions): صاحبه والأدمن بس |

| دعاه (referred_by) + هل انصرفت نقاط الدعوة | داخلي |
| رمز الدعوة | تلقائي |

**الأدوار (Roles):** زائر، ضيف، طالب، مشرف جامعة (مربوط بجامعة أو أكتر)، أدمن.

## ٤. النقاط (قواعد نهائية)

| الحدث | النقاط | متى بتنزل |
|---|---|---|
| تجربة على مشروع | +10 مع صور، و+2 بدون صور | **لما يوافق عليها الأدمن** |
| مبنى بالمدينة | +5 | **لما ينقبل** |
| دعوة صاحب | +10 للداعي و+5 للمدعو | لما **أول تجربة** للمدعو تنقبل. مش عند التسجيل. بسقف 10 أصدقاء |
| استبدال | −النقاط | الطالب بيحوّلها لـ **كوبون خصم على المتجر** |

- الرتب: مبتدئ (0)، مساهم (20)، صانع (50)، خبير (120)، من `rules.ts`.
- **كل النقاط بتمرق من خدمة وحدة** (`platform_points.ledger`)، ورصيد الطالب = مجموع سجلّه. ما في حقل رصيد بينكتب مباشرة.
- **سعر الكوبون** (كم نقطة مقابل كم دينار) **لسا ما انحسم**. الإعدادات بلوحة الأدمن، والقيمة المبدئية: 50 نقطة = 5 د.أ خصم.
- قاعدة "بعد مشروعين مجانيين لازم يسجّل" (`paywall.ts`) بتضل، بس بتنعمل بدروبل (عداد للزائر، وبعدها نموذج التسجيل).

## ٦. المتجر والطلب

- **سلة المشروع:** كل قطعة مربوطة بمنتجها. الطالب بيختار بين البدائل، والتكلفة بتنحسب لحالها. وفي زر **"ضيف كل القطع للسلة"** بيحط كل المنتجات المختارة بسلة Commerce بالكميات.
- **الملاحظات:** بتظهر تحت القطعة بالبرتقالي، زي الموقع الحالي: "القطعة الأصلية نفدت، وهاد أقرب بديل"، "مجموعة من المتجر"، "إذا بدك بنطبعها لك بخدمة الطباعة ثلاثية الأبعاد"، "مش متوفرة حالياً، اسألنا عن بديل".
- **القطع اللي ما إلها منتج** (علب بتنطبع وغيرها) ما بتنضاف لسلة Commerce. بتطلع بقائمة "بدها طلب خاص"، وزر واتساب.
- **الـ checkout:** الاسم، الموبايل، المدينة، العنوان، ملاحظات. **ممنوع ذكر توصيل مجاني.** رسوم التوصيل بتنحسب حسب إعدادات Commerce.
- **الدفع:** شوف القسم ١١. المبدئي: كاش عند التوصيل.
- **الطلب بالواتساب** بيضل كخيار، ورسالته بتذكر المنتج البديل والملاحظة.
- **الكوبونات:** حقل كوبون بالسلة.
- **رقم الواتساب الحقيقي** لسا وهمي (962790000000). بيتحط بإعدادات `platform_core`.

## ٧. المجتمعات والدردشات

**ثلاث مساحات، مش وحدة.** كلها نفس نوع المحتوى ونفس الردود، والفرق بصلاحية النشر:

| المساحة | مين بينشر | ملاحظة |
|---|---|---|
| **المجتمع العام** | أي طالب مسجّل | لكل الجامعات. المنشور بيقدر يذكر جامعة بعلامة `@` |
| **مجتمع الجامعة** | طلاب تلك الجامعة بس | التحقق من الجامعة المربوطة بالحساب |
| **الإعلانات** | المشرف/الأدمن بس | قناة من الفريق — بتنقرأ من الكل وما بينشر فيها إلا المشرف |

- **منع النشر لازم يكون على مستوى الخادم مش الواجهة.** الإعلانات ونوع «موعد تسليم» بينرفضوا من دروبل نفسه لو حاول حدا ينشر من برّا.
- **ذكر الجامعة (`@`) بالمجتمع العام:** الطالب بيختار جامعة من قائمة فبتنضاف `@JUST` للنص. عند العرض بتصير رابط لمجتمع تلك الجامعة، وفوق المنشورات بيطلع شريط بالجامعات **المذكورة فعلاً** بيفلتر فيهم. المطابقة بتفهم الاختصار (`@YU`) والاسم العربي (`@اليرموك`).
- **«مجتمعي» بالقائمة:** خانة وحدة بتنفتح على الثلاثة — العام، مجتمع جامعته، الإعلانات — مع شارة حالة لكل وحدة (`عضو` / `تتابعها` / `انضم`). بتظهر للزائر كمان مش للمسجّل بس.
- **المساحة الفاضية بتقترح مش بتعتذر:** بدل «ما في منشورات»، أربع مواضيع بداية بتفتح نموذج الكتابة معبّى بالنوع والعنوان. وشرائح الفلترة بتنخبّى لحد ما يصير في منشورات.
- **الطالب بينشر بمجتمع جامعته بس** (ومجتمعه العام)، والتحقق من الجامعة المربوطة بحسابه.
- **أنواع المنشورات:** سؤال تقني، شغلي، أدوّر على شريك، مصدر مفيد، بدي تعديل على مشروع، وموعد تسليم (**للمشرف بس**، بتاريخ، وبيطلع بشريط التنبيهات أعلى المجتمع مع عدّاد الأيام).
- **الردود:** تعليقات مرتبة بالتاريخ على كل منشور.
- **المشرفين:** لكل جامعة مشرفين. أي طالب بيقدّم طلب إشراف، والأدمن بيوافق. المشرف بيخبّي منشور أو رد بمجتمعه.
- **"N منشورات جديدة" و"علّمها مقروءة":** بتنحفظ بحساب الطالب بدل المتصفح.
- **الدردشة الخاصة بين الطلاب:** شوف القسم ١١.

## ٨. لوحة الأدمن (`/admin/platform`)

1. **المشاريع:** إضافة وتعديل بنفس محرر الموقع الحالي (`admin/editor.ts`): الخطوات، والمميزات، والتحديات، ومجموعات القطع مع اختيار المنتجات من المتجر ببحث.
2. **"مشروع من فكرة":** الأدمن بيكتب الفكرة، والصفحة بتولّد له نص جاهز. بينسخه لـ Claude.ai (مجاني)، وبيلصق الرد (JSON) بالصفحة. الصفحة بتفحص الرد، وبتعرض القطع المقترحة مع المطابقة من المتجر للمراجعة، وبعدها بتنحفظ كمسودة. **ما في مفتاح API**.
3. **طوابير الموافقة:** التجارب، والمباني، وطلبات الإشراف، وطلبات التعديل على المشاريع. موافقة أو رفض بالجملة، والنقاط بتنزل تلقائياً عند الموافقة.
4. **المستخدمين والنقاط:** بحث، تعديل الدور، تعديل يدوي للنقاط (بينسجّل كسبب "تعديل من الإدارة")، وسجل كل طالب.
5. **الطلبات:** طلبات Commerce بحالاتها.
6. **الإعدادات:** رقم الواتساب، روابط الإنستغرام وقناة الواتساب، سعر الكوبون بالنقاط، ونص الشروط.
7. **تحديث كتالوج أبيلا:** رفع ملف `abela.json` جديد، وبيطلع تقرير قبل التطبيق: جديد / سعر تغيّر / انشال. التطبيق بعد التأكيد.

## ١٠. الاستيراد (سكربتات drush)

| الأمر | بيقرأ | بيعمل |
|---|---|---|
| `drush platform:import-parts` | `abela.json` | منتجات Commerce (تحديث بالمكان أو إضافة أو تعطيل)، بتقرير قبل التطبيق |
| `drush platform:import-projects` | `projects.json` + `details.json` + `partmap.json` + `partalt.json` | مشاريع مع مجموعات القطع المربوطة |
| `drush platform:import-universities` | `universities.ts` + `unimail.ts` (مصدّرين JSON) | الجامعات (28) باختصارها ومدينتها ونطاقات البريد |
| `drush platform:import-spaces` | `spaces.ts` | مساحات المجتمع: المجتمع العام والإعلانات + مساحة لكل جامعة |

**كل سكربت لازم يكون:**
- قابل للتكرار: التشغيل مرتين ما بيعمل تكرار.
- فيه وضع تجربة (`--dry-run`) بيطبع شو رح يصير بدون ما يكتب.

## ١١. قرارات لسا مفتوحة (بدها رد نغم)

| القرار | المبدئي لحد ما ينحسم |
|---|---|
| الدفع: كاش عند التوصيل بس، ولا كمان CliQ أو بطاقة؟ | كاش عند التوصيل، وCliQ جاهز كخيار يدوي |
| الدردشة الخاصة بين الطلاب (رسائل مباشرة)، ولا بس المجتمعات وتعليقات المباني؟ | المجتمعات والتعليقات. والرسائل الخاصة بمرحلة لاحقة |
| المستشار الذكي و"قطع من صورة" (بدهم مفتاح API مدفوع) | الشات بدون AI، والميزتين مخفيات لحد ما يصير في مفتاح |
| سعر الكوبون بالنقاط | 50 نقطة = 5 د.أ، وبيتعدّل من الإعدادات |
| برنامج السفير | صفحة ونموذج بس |
| المجسمات ثلاثية الأبعاد | بتنتقل زي ما هي، والتحسين بعدين |
| تطبيق الموبايل (Capacitor بنوفاتيرا) | مؤجّل |
| رقم الواتساب، والإنستغرام، وقناة الواتساب | بالإعدادات، بانتظار الأرقام والروابط |
| الشروط والأحكام | مسودة، بانتظار مراجعة قانونية |
